## Notes
GAPS AND ASSUMPTIONS:

1. Input resolution fallback: Step-4 keeps _design_read_prior_design as a fallback when ZBUILD_STAGE_INPUTS is absent. If the prior-output-reader ADR-050 Tier-1/Tier-2 seam is fully superseded by input-resolve.sh in a live dispatch, the fallback is dead code. But existing unit tests that inject ZBUILD_CYCLE_FEEDBACK_DIR without going through lifecycle.sh will break if the fallback is removed entirely. Safest approach: read from index first, fall back to the tier-1/tier-2 reader. If product expectation is clean deletion, the implementation agent should also update the test fixtures.

2. Router budgets key name: The manifest uses config.router.timeout_s and config.router.max_turns per _route_resolve_knob. The issue references #1816 'router budgets'. The plan plugin uses config.router.{retries, retry_on_exhaustion} — these are additive. The defaults I propose (timeout_s:600, max_turns:45) are conservative; the template override (600s, max_turns:0) still wins at runtime. The implementation agent should confirm the exact knob names by checking _route_resolve_knob's 4th arg (the manifest key).

3. design_result declared output: The v2 sidecar design-verdict.json is read by _verdict_read_stage_sidecar generically — it is NOT a declared output in the manifest and should not be. Do not add it as an output entry. The existing mechanism already reads it.

4. rc=130 SIGINT: The issue says rc ∈ {0,1}; SIGINT (rc=130) is a hard abort, not a stage outcome. Propagating rc=130 without writing a result is correct — the engine treats an aborted dispatch differently from a failed one. No change needed for the SIGINT arm except removing return 2 on other paths.

5. ADR-063 §3/§4: The issue says §3/§4 (the design-gate check that refuses a partial design) is out of scope for plugin.sh — it belongs in design-gate. This plan deliberately scopes only §1/§2 (prompt injection) to the design plugin.

6. 'did_not_finish' vocabulary: The cycle-orchestrator already reads disposition=interrupted from the blob (cycle-orchestrator.sh:2335). The test fixture (design-timeout-exhaustion-halt-1261-test.sh) already uses this vocabulary. No orchestrator changes needed.

7. Cleanup hook: The issue says 'if it has nothing to free, the hook is absent and that is recorded, not implied.' The manifest has no cleanup hook today; lifecycle.sh already emits plugin.cleanup.absent (rc=0). No manifest change needed for cleanup.

8. Step-6 has estimated_lines:0 because it is a verification step, not a code-writing step. The CLAUDE.md 'state the red step' requirement means the PR body (not a file in scope) records the failing assertion.

9. WIRING: The wiring for this migration is the manifest itself (plugins/agent/design/manifest.yaml) — its result_contract:2 declaration gates the engine's strict v2 reading. The implementation files (plugin.sh + tests) are the implementation.

# Design: design plugin → contract v2 + ADR-063 §1/§2 (iteration 3)

## Architectural decision summary

**Goal**: Migrate `plugins/agent/design` to the v2 result contract (always-written
`design-verdict.json` sidecar with `result_contract:2`, `verdict`, `disposition`) and
inject live `timeout_s`/`max_turns` into the prompt so the model can emit a best-effort
design before being cut off (ADR-063 §1/§2).

**Context**: The build stage added `_design_write_result` on all exit paths and injected
budget guidance. Three concrete bugs remain unfixed; they cause four test failures:

1. **`plugin.sh:651` pipe subshell** — `cat "$output_design_md" | atomic_write "$output_design_md"`
   runs `atomic_write` in a pipe subshell. The test mock sets `_SIDECAR_AT_ATOMIC_WRITE="PRESENT"`
   inside the mock, but the update is invisible to the main shell → SPEC-1 assertion
   `expected: PRESENT, got: UNSET` fails. Fix: stdin redirect (no pipe) so `atomic_write`
   runs in the current shell.

2. **`plugin.sh:292-293` heredoc split phrase** — The heredoc emits:
   ```
      ...never the answer. You MUST
      actively search the repo (Read/Grep/Glob)...
   ```
   `grep -q 'MUST actively search the repo'` never matches a multi-line file by default
   → SPEC-8 fails. Fix: join to a single line.

3. **`design-router-timeout-reiter-test.sh:252-255` stale guard** — The guard asserts
   `design-verdict.json` is ABSENT on the happy path. The v2 contract now writes
   `verdict=pass, disposition=complete` there → assertion fails. Fix: accept a
   pass-disposition sidecar as valid.

**Decision**: Three surgical edits — two in `plugin.sh`, one in the router-timeout test.
WIRING remains `manifest.yaml`; its SPEC-4 pass→fail flip becomes detectable once SPEC-1
passes at HEAD (the current test-file failure masked the flip).
