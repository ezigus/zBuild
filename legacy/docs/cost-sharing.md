# Cost Sharing — Cross-Machine Optimization

**Issue:** [#460](https://github.com/sethdford/shipwright/issues/460)
**Status:** Active (since Shipwright v3.6.1)

Every Shipwright pipeline run generates `cost-breakdown.json` summarizing token
usage and Claude API cost by pipeline stage and loop iteration. Issue #460
exposes this data as a **dedicated, separately-named GitHub Actions artifact**
so the weekly self-optimization workflow — and any external analytics tooling —
can pull cost data from recent runs across machines and fold it into a shared
rolling baseline.

## Artifact Contract

| Property         | Value                                                              |
|------------------|--------------------------------------------------------------------|
| **Artifact name** | `cost-breakdown-issue-<N>-run-<RUN_ID>`                           |
| **Producer**      | `.github/workflows/shipwright-pipeline.yml` (every run)           |
| **Content**       | `.claude/pipeline-artifacts/cost-breakdown.json` (single file)    |
| **Retention**     | 30 days (vs 7 days for the combined `pipeline-logs-*` artifact)   |
| **Upload mode**   | `if: always()` — uploaded even on failed runs                     |
| **Stability**     | Name + path treated as semver-stable. Bump major to rename.        |

The 30-day retention deliberately outlives the weekly optimize cron so a single
missed Sunday does not lose data. Failed runs are the most valuable for tuning,
hence the `if: always()` guard.

## Schema

`cost-breakdown.json` is generated by
[`cost_generate_breakdown`](../scripts/sw-cost.sh) and has this shape:

```json
{
  "pipeline_id": "issue-460-run-12345",
  "issue": "460",
  "generated_at": "2026-05-19T00:00:00Z",
  "summary": {
    "total_input_tokens":   123456,
    "total_output_tokens":   12345,
    "total_cost_usd":        1.23,
    "iteration_count":       5,
    "stage_count":           8
  },
  "by_stage": [
    {
      "stage":         "build",
      "input_tokens":  100000,
      "output_tokens":  10000,
      "cost_usd":       1.05,
      "count":          3,
      "models":         ["sonnet", "opus"]
    }
  ],
  "by_iteration": [ ... ]
}
```

The merged output produced by `cost_merge_breakdowns` is a superset that adds
top-level `version`, `sources`, and a flat `by_stage[]` with running per-stage
totals across all input artifacts. Each stage entry gains a `sources` field
recording how many input runs contributed to it.

## Consumer Pattern — Optimize Workflow

`.github/workflows/shipwright-optimize.yml` (Sunday 03:00 UTC) downloads the
N most-recent pipeline artifacts matching `cost-breakdown-*`, calls
`cost_merge_breakdowns` to aggregate them, and folds the result into the
rolling baseline via `cost_apply_merged_to_baselines`. The merged file lives
on the `shipwright-data` orphan branch under `baselines/`.

```bash
# Equivalent local invocation for debugging:
mkdir -p /tmp/cost-merge
gh run list --workflow=shipwright-pipeline.yml --status=completed --limit=20 \
  --json databaseId --jq '.[].databaseId' \
  | while read -r run_id; do
      gh run download "$run_id" \
        --dir "/tmp/cost-merge/run-$run_id" \
        --pattern 'cost-breakdown-*' 2>/dev/null || true
    done

shipwright cost merge /tmp/cost-merge ~/.shipwright/baselines/merged.json --apply-baselines
```

Required permission: `actions: read` (scoped per-job in
`.github/workflows/shipwright-optimize.yml`).

## External Consumers

External tooling (dashboards, telemetry pipelines, alerting) can rely on this
artifact contract:

- **Name pattern** is stable: `cost-breakdown-issue-<N>-run-<RUN_ID>`. The
  numeric run ID makes cross-run collisions impossible.
- **Content** is a single `cost-breakdown.json` file with the schema above.
- **Discovery**: `gh api repos/{owner}/{repo}/actions/artifacts?per_page=100`
  followed by `gh run download <run_id> --pattern 'cost-breakdown-*'`.

## Opting Out

The dedicated upload step is conditioned on `steps.claim_check.outputs.skip
!= 'true'` (the same gate every other upload uses) and on the breakdown file
existing. To suppress it for a specific run, set the repo variable or branch
input that triggers the claim-check skip, or delete the breakdown file in a
pre-upload step.

## Implementation

| Component | File |
|-----------|------|
| Upload step (producer) | `.github/workflows/shipwright-pipeline.yml` |
| Download + merge (consumer) | `.github/workflows/shipwright-optimize.yml` |
| Merge library | `scripts/lib/cost/share.sh` |
| Baseline integration | `scripts/lib/cost/baselines.sh` (reused) |
| Test harness | `scripts/sw-lib-cost-share-test.sh` |
| CLI subcommand | `shipwright cost merge <input_dir> [out_file] [--apply-baselines]` |
