#### security (score: 7/10)
- [medium] plugins/agent/intake/plugin.sh:114 — The TERM trap set inside \`intake_run\` is never cleared (no \`trap - TERM\` on normal return), so it persists in any shell that sources the plugin and calls the function directly; if SIGTERM arrives after \`intake_run\` has already returned successfully, the trap fires \`_intake_write_result fail broken\` and then \`exit 1\`, writing a spurious failure result over the correct one and killing the surrounding shell.
- [low] plugins/agent/intake/plugin.sh:110 — The fallback \`_intake_art\` is derived from the \`state_file\` argument via \`dirname "${2:-}"/artifacts\`; the repo facts state explicitly that a plugin deriving an artifact path from its state file is a defect (ADR-055 §1), and a crafted state_file containing \`..\` components would redirect writes to an unintended directory.
- [low] plugins/agent/intake/plugin.sh:49 — \`_intake_write_result\` silently returns 0 (via \`|| return 0\`) if either \`jq\` invocation fails — including when \`$data_json\` is malformed JSON — so callers cannot distinguish a successful write from a suppressed failure, and the result file may be absent on a terminal exit path without any error signal.
- [low] plugins/agent/intake/plugin.sh:43 — The jq variable \`--argjson rc 2\` names the \`result_contract\` version field as \`rc\`, which universally means return-code in shell contexts; a future maintainer could replace the literal \`2\` with the actual return code of a command, silently corrupting the \`result_contract\` field.

#### sre (score: 7/10)
- [medium] plugins/agent/intake/plugin.sh:295 — SIGTERM arriving after \`_intake_write_result "pass" "complete"\` (line ~295) but before process exit will overwrite a valid pass result with \`fail/broken\`; in container runtimes that send SIGTERM for graceful drain, a cleanly-completed intake stage appears failed to the engine, triggering a retry or pipeline abort.
- [low] plugins/agent/intake/plugin.sh:59 — \`atomic_write\` is called with \`2>/dev/null || true\`, suppressing both the error log that atomic_write emits on disk-full / permission-denied and the non-zero return; if the write fails the result file is silently absent and the engine sees a contract violation with no diagnostic to explain why.
- [low] plugins/agent/intake/plugin.sh:114 — The TERM trap set inside \`intake_run\` is never cleared with \`trap - TERM\` on function exit; it persists in any shell that calls \`intake_run\` as a function (rather than a subprocess), so a subsequent SIGTERM to that shell will call \`_intake_write_result\` with stale or out-of-scope \`_intake_art\` and then \`exit 1\`, terminating the shell unexpectedly.
- [low] plugins/agent/intake/plugin.sh:42 — Both jq invocations in \`_intake_write_result\` use \`|| return 0\` — if jq is absent or produces invalid JSON the function returns success, no result file is written, and no log entry records the failure; the calling code proceeds as if the write succeeded.
- [low] plugins/agent/intake/plugin.sh:286 — Branch creation failure is reported as \`disposition: misconfigured\`, but the failure can be transient (network outage, remote temporarily unavailable, upstream permission lag); if the engine's response table treats \`misconfigured\` as non-retryable operator action, a retryable failure will be treated as a permanent one.
