Gap 11 in the Context/gaps section explicitly names the exact problem the finding raises: in combined `--resume --from-stage <s>` mode, once `skip_until_stage` is cleared when the target unit is found, `resume_mode` remains `true`, causing the resume skip guard to activate for all subsequent units marked complete. The Decision paragraph requires the fix: in both dispatch-unit arms (cycle:* and stage:*) of `main()` in runner.sh, immediately after clearing `skip_until_stage`, also set `resume_mode=false` — preventing the skip guard from firing for any unit after `<s>`; pure resume runs never set `skip_until_stage` so this path is unreachable for them.
