## Notes
1. The gate_aggregator_result path is already available in ZBUILD_STAGE_INPUTS when pr-open runs inside pr-delivery (shared process, pr-delivery declares the input). Adding it to pr-open's own manifest satisfies ADR-055 §1 without requiring new plumbing. 2. Convergence detection scans ALL keys in `.cycle_iterations` for any with `status == max_iterations` — not just `build_test_cycle` — so the fix is general. 3. The PR body must show the convergence state for ALL cycles that ran, not just unconverged ones (acceptance criterion: 'body shows the cycle's iterations used out of the maximum'). For converged cycles this is informational; for unconverged it is the prominent warning. 4. When an existing PR is updated via `gh pr edit`, `--draft` cannot be set after create; `gh pr ready --undo` would be needed to convert an existing non-draft to draft. The plan must handle the update-existing-PR path: if the PR already exists and should be draft, call `gh pr ready <num> --undo` (converts to draft). This is a subtle edge case not called out in the issue but required for correctness — added as a note; if gh CLI version does not support `--undo`, the step should emit a warning rather than failing. 5. The `_draft_bool` variable is also used in pr-result.json; once forced to `true` it should flow through correctly into the recorded artifact. 6. Tests must confirm they are red on main by asserting draft=true in pr-result.json; the current code always writes `_draft_bool` from `_TPL_PR_DRAFT` only, so these assertions will fail against main.

### DESIGN DECISIONS (from the design stage — honor these directives; they refine the plan)
# Design: Draft PR on Failed / Unconverged Run (Issue #1799)

## Architectural Decision Summary

**Goal:** When a zBuild run ends in a failed state or a build cycle reaches `max_iterations` without converging, the PR it opens must be a draft, and the PR body must name the failing gate and convergence state. Passing, converged runs continue to open non-draft PRs.

**Context:** `plugins/tool/pr-open` already has draft-mode support via `_TPL_PR_DRAFT` (the template's `pr_draft:` key). The state file written by the runner records `.status` (e.g. `"failed"`) and `.cycle_iterations[<id>].status` (e.g. `"max_iterations"`). Both are available to `_pr_open_run_inner` via the `state_file` argument it already receives. The gate-aggregator writes a result artifact with `failed[]` and `reason` that identifies which gates blocked convergence; pr-delivery already declares `gate_aggregator_result` as an optional input, and pr-open already reads from `ZBUILD_STAGE_INPUTS` (the calling stage's inputs index, ADR-055 §1).

**Decision:** Add state-aware draft forcing directly in `_pr_open_run_inner`: read `state.status` and `cycle_iterations` from the state file to override `_draft_bool` to `true` on a failed or unconverged run. Extend `_pr_open_compose_body` (in `advisory-section.sh`) to accept and render a convergence section when the run was not converged. Declare `gate_aggregator_result` as an optional input in the pr-open manifest. The `_TPL_PR_DRAFT=true` path continues to take effect before the new state check, so it remains authoritative.
Where a design decision above conflicts with the plan, follow the design decision.
