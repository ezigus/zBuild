#### security (score: 8/10)
- [medium] plugins/agent/spec-coverage/plugin.sh:183 — The mktemp fallback \`"${TMPDIR:-/tmp}/scv_rc.$$"\` uses the process PID as the sole disambiguation token — an attacker with local filesystem access who can predict the PID (or enumerate /proc) could pre-place a symlink at that path and redirect the \`printf '%d' "$?" > "$_scv_rc_tmp"\` write to an arbitrary target, or plant a crafted value that \`_router_rc_classify\` will receive as the router exit code; impact is bounded (only a 1–3-digit integer is written) but the pattern is a classic TOCTOU and is new to this change.
- [medium] plugins/agent/spec-correspondence/plugin.sh:253 — Same predictable-PID temp-file fallback \`"${TMPDIR:-/tmp}/sc_batch_rc.$$"\` as the spec-coverage change — identical attack surface and impact bound, introduced by this change in the \`_sc_batch_rc_tmp\` assignment.
- [low] plugins/agent/review-report/plugin.sh:170 — The disposition string captured from \`_router_rc_classify\` is placed into \`_cycle_emit\` (via the caller) as the literal value \`"disposition=${_first_unf_disposition:-unfinished}"\` without sanitization — if a lens subshell were to write a non-integer or multi-line value to its \`.rc\` file, the classification path could produce a disposition string containing shell-special or JSON-special characters that flow into the emitted event; the \`disposition_unfinished\` gate in the orchestrator constrains this to known words in the happy path, but the review-report codepath does not pass through that gate.
- [low] plugins/agent/review-report/plugin.sh:165 — The \`.rc\` file content \`_rr_lens_rc\` is read from disk and used directly in \`[[ "$_rr_lens_rc" -ne 0 ]]\` with no numeric validation; a lens subshell that writes non-integer content (e.g. an error message) causes bash's integer comparison to abort the function under \`set -uo pipefail\`; this is pre-existing behavior for the read, but this change is the first to forward the raw value to \`_router_rc_classify\`.

- [low] plugins/agent/spec-coverage/plugin.sh:187 — If the bash subshell running \`route_to_model\` is OOM-killed or externally SIGKILLed before the trailing \`printf '%d' "$?" > "$_scv_rc_tmp"\` executes, the temp file is empty; \`cat || printf '0'\` returns \`0\`, \`_scv_router_rc\` stays 0, and the disposition falls back to \`complete\` — convergence suppression would not fire for an OOM-killed model call.
- [low] plugins/agent/spec-correspondence/plugin.sh:255 — Same OOM-kill gap as spec-coverage: if the subshell executing \`route_to_model\` inside \`_sc_call\` is killed before the trailing printf, \`_sc_batch_router_rc\` reads \`0\` from the empty temp file, and disposition stays \`complete\`.
- [low] core/pipeline/cycle-orchestrator.sh:2583 — If \`verdicts_blob\` contains malformed JSON, the jq command at line 2583 silently fails (errors suppressed by \`2>/dev/null\`) and the while-loop body never executes, leaving \`_iter_did_not_finish=0\`; an unfinished member whose verdict blob is unparseable is invisible to the new convergence suppression block, allowing false convergence.
- [low] core/pipeline/cycle-orchestrator.sh:2623 — The generic suppression applies to ALL cycle types, not only \`design_verify_cycle\`; in a \`build_test_cycle\` where the build member is complete but a test/gate member is unfinished, the new block fires (the build-specific block does not, because \`_build_disposition\` is complete) and suppresses convergence — this broader blast radius has no test coverage in the added test file and relies entirely on the build-block's \`converged==1\` guard remaining the first check.
