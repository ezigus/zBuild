## Review Report

**Merge Readiness:** advisory

13 merge-readiness finding(s) across 6 lens(es) (0 critical, 1 high).

### Lens Findings

#### correctness (score: 7/10)
- [medium] plugins/tool/pr-open/lib/advisory-section.sh:129 — If a \`max_iterations\` cycle entry in the state file is missing \`iterations_used\` or \`max_iterations\` fields, \`_convergence_json\` carries JSON \`null\` for those values and the rendered convergence line shows \`(null/null iterations)\` instead of real counts, giving the operator no usable information.
- [low] plugins/tool/pr-open/lib/advisory-section.sh:169 — The \`_extra\` block (convergence warning and failing-gate lines) is appended after \`"Generated by zBuild automation."\`, so the safety-critical operator notice appears below the footer rather than in a prominent position; acceptance criteria check for string presence, not position, so tests pass, but the warning is easy to overlook.
- [low] plugins/tool/pr-open/plugin.sh:140 — When \`state.status\` is \`"failed"\` (SPEC-1) but no cycle has \`status == "max_iterations"\` (SPEC-2 does not apply), \`_convergence_json\` remains \`[]\` and \`_pr_open_render_convergence_section\` emits nothing; SPEC-3 says the body must include a convergence section when SPEC-1 applies, so a failed-but-converged run produces a draft PR with no convergence text, leaving the operator with only the gate section (if present) as context.

#### performance (score: 8/10)
- [low] plugins/tool/pr-open/plugin.sh:140 — \`_max_iter_count\` is computed with a dedicated \`jq\` process then \`_convergence_json\` is computed with a second \`jq\` process using the identical \`.cycle_iterations … select(.value.status == "max_iterations")\` filter; \`_max_iter_count > 0\` is fully implied by \`_convergence_json != "[]"\`, so the first spawn and the numeric check are dead weight.
- [low] plugins/tool/pr-open/plugin.sh:133 — Three separate \`jq\` subshells are forked on \`state_file\` (status, count, convergence JSON) where a single \`jq\` call producing a composite object would suffice; the overhead is bounded to one PR-open per run but the pattern sets a precedent for accumulation.
- [low] plugins/tool/pr-open/lib/advisory-section.sh:137 — \`_pr_open_render_gate_section\` forks three \`jq\` subshells on the same \`gate_path\` (verdict, failed list, reason) where a single \`jq\` call projecting all three fields at once would eliminate two process-spawn round-trips.

#### red-team (score: 6/10)
- [high] plugins/tool/pr-open/plugin.sh:388 — When an existing open PR is found, the code calls \`gh pr edit\` with only \`--title\` and \`--body\`, never consulting \`_gh_args\`; the \`--draft\` flag forced by the new SPEC-1/SPEC-2 logic is silently dropped, so a non-draft PR opened by a prior passing run remains non-draft after a failed or unconverged re-run.
- [low] plugins/tool/pr-open/lib/advisory-section.sh:145 — Gate-aggregator \`failed_gates\` and \`reason\` strings are interpolated into the PR body via bare \`printf\` without the \`esc\` sanitiser (strips ANSI, control chars, escapes \`\\`,\`[\`,\`]\`,\`<\`,\`>\`) that every other value rendered in this file passes through.
- [low] plugins/tool/pr-open/lib/advisory-section.sh:129 — \`cycle_id\`, \`iterations_used\`, and \`max_iterations\` extracted from the state file are interpolated into the PR body via \`jq -r\` string interpolation without the \`esc\` sanitiser used for all advisory findings rendered elsewhere in this file.

#### scope (score: 10/10)
No findings.

#### security (score: 8/10)
- [low] plugins/tool/pr-open/lib/advisory-section.sh:132 — The \`reason\` and \`failed_gates\` fields extracted from gate_aggregator_result are reflected verbatim into the PR body without any sanitization; if the gate-aggregator artifact were compromised, arbitrary markdown or HTML could be injected into the published PR.
- [low] plugins/tool/pr-open/lib/advisory-section.sh:16 — The \`cycle_id\` field from pipeline-state.json is interpolated directly into PR-body markdown via jq's \`\(.cycle_id)\` without sanitization; a malicious or malformed state file could inject arbitrary markdown into the PR.

#### sre (score: 6/10)
- [medium] plugins/tool/pr-open/plugin.sh:497 — The emit_event at plugin.result emission does not include draft status or the reason draft was forced (failed_status or max_iterations), so operators cannot identify forced-draft events in structured logs without inspecting pr-result.json manually.
- [medium] plugins/tool/pr-open/plugin.sh:388 — The existing-PR update path (gh pr edit) does not pass --draft or call gh pr convert-to-draft, so a failed re-run that finds an existing non-draft PR updates the body with the convergence warning but leaves the PR as non-draft, violating the issue's requirement that a failed run never presents its output as ready to merge.
- [low] plugins/tool/pr-open/lib/advisory-section.sh:178 — The convergence and gate warning blocks (_extra) are appended after 'Generated by zBuild automation.' at the end of the PR body, reducing operator visibility of the non-convergence alert compared to the issue's example placement.
