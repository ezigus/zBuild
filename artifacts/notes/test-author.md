## Changes made in this run (iteration 5)

### Fixed DSCLA-10 (test-author finding 1 — open from previous iteration)

**Problem:** The previous DSCLA-10 block called `eb_compose_known_types` and
checked that `pipeline.refused.claimed` appears in the returned set. The
finding said this does not invoke the actual emitted-coverage check that scans
source files; a coverage tool that misread/skipped the emission site would still
pass the test.

**Base-code context:** In the base code's `plugin.sh`, `pipeline.refused.claimed`
is NOT emitted as a literal. So simply running the coverage check as the "When"
would pass on base code (no unregistered emission found), making the test
incorrectly green on base code.

**Fix:** Two-part structure in the DSCLA-10 block:
1. **Given check** (via `eb_compose_known_types`): on base code, `pipeline.refused.claimed`
   is absent from `event-schema.json`, so this check fails immediately with
   `assert_fail "[DSCLA-10] Given: pipeline.refused.claimed must be in config/event-schema.json"`.
   This is the correct red step on base code.
2. **When/Then** (runs only when Given is satisfied on new code): invoke
   `bash tests/unit/event-schema-emitted-coverage-test.sh` as a subprocess,
   capture exit code and output. If exit 0 → `assert_pass`. If exit non-zero AND
   output contains "pipeline.refused.claimed" → `assert_fail`. If exit non-zero
   but output does NOT contain "pipeline.refused.claimed" → `assert_pass` (failed
   for a different unrelated event, which is not what DSCLA-10 tests).

**SIGPIPE fix:** The assert_fail message originally used `grep ... | head -3`
(bare `| head` violates repo rules). Replaced with `${_dscla10_out:0:400}` string
slice.

**Base code behavior:**
- `pipeline.refused.claimed` not in `event-schema.json`
- `eb_compose_known_types` does not return it
- `! grep -qxF ...` is TRUE → `assert_fail "[DSCLA-10] Given: ..."` → FAILS ✓

**New code behavior:**
- `pipeline.refused.claimed` IS in `event-schema.json`
- `eb_compose_known_types` returns it
- Given check passes → coverage check runs → exits 0 → `assert_pass` ✓
