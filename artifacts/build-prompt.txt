## Notes
1. INPUTS STAY []: Intake reads state/platforms.json directly (written by core/detect/platforms.sh before intake runs) — this is not a declared inter-stage artifact, it is a runtime side-channel. The acceptance criterion about no-constructed-artifact-paths applies to INPUT artifacts; the grep test should confirm no path like ${artifact_dir}/... appears as a consumer path in plugin.sh. The state_dir-relative writes (scope-manifest.md, intake.md) are OUTPUT paths that still appear in code and in the manifest — that is expected under the current engine (ADR-055 §1's full path-resolution via #1826 is not yet complete). 2. SCOPE_MANIFEST PRIMARY: The issue says 'If this plugin already declares one, say so and move on' about primary: true — the existing primary is scope-manifest.md (markdown), which cannot carry result_contract/verdict/disposition/reason. Under v2, the primary must be the JSON result file. A new intake-result.json output becomes primary and scope-manifest.md drops primary: true. 3. CLEANUP: Intake holds no live resources (no spawned process groups, no locks, no open handles beyond what atomic_write closes immediately). The hook is absent. ADR-054 §7 says 'if it has nothing to free, the hook is absent and that is recorded, not implied' — recorded by a manifest comment and a test assertion that the manifest declares no cleanup hook. 4. ROUTER BUDGET VALUES: Intake makes no LLM calls today (T1 tier, no route_to_model). The #1816 requirement is that router budgets are declared in the manifest so the template override can win. Reasonable defaults: timeout_s: 120 (generous for gh API calls), max_turns: 0 (no turns needed). 5. INTERRUPTION PATH: The issue lists 'interruption' as an exit path that must produce a v2 result. Intake installs no signal trap directly — interruption arrives as a SIGINT/SIGTERM killing the subshell. The DoD says 'interruption' but ADR-054's interruption path is the engine's own signal trap writing a broken disposition if no result was left. For a T0-style synchronous plugin like intake, the practical approach is ensuring every normal exit path writes the result — a genuine mid-flight kill will leave no result and the engine classifies it as broken per ADR-054 §4. The test drives the declared paths; the interruption path is addressed by the engine's existing broken-result fallback. 6. GOLDEN DIFF: The 'before/after golden diff on the stage's own output' means the state/scope-manifest.md and state/intake.md content must be identical between a v1 and v2 run on the same input. This can be captured as a fixture (the expected content of both files for a canonical ZBUILD_GOAL) asserted in the test. The intake-result.json is NEW (no v1 baseline), so it is not part of the diff. 7. TRIPLICATED SCOPE-MANIFEST: The issue says intake is the 'producer half of the triplicated scope-manifest.md declaration.' Under v2 intake declares that output once (already done in manifest). The 'build references it' part is a build manifest change that is OUT OF SCOPE for this issue — the issue says 'each plugin moves on its own' and the engine reads v1 and v2 side by side. 8. TESTS IN intake-branch-test.sh: All rc=2 assertions there test _intake_create_workspace_branch (a lib function), not intake_run. They do not need updating — lib functions may return any code; only the contract-facing intake_run is narrowed to {0,1}.

## DESIGN DECISIONS (from the design stage — honor these directives; they refine the plan)
# Design: Migrate intake plugin to contract v2 (issue #1837)

## Architectural Decision Summary

**Goal.** Move `plugins/agent/intake` to the v2 stage contract (ADR-054 §4/§5/§6, ADR-055): rc ∈ {0,1} on every `intake_run` exit path; `intake-result.json` written atomically on every terminal path; `result_contract: 2` declared in the manifest; `valid_verdicts: [pass, fail]` replacing the v1 `[]`; router budget knobs declared so the template layer can override them; `primary: true` moved from the markdown `scope_manifest` output to the new JSON result output; plugin-specific run metrics (`goal_len`, `platform_count`) moved from the `plugin.result` event into the result file's `data` object.

**Context.** Today `intake_run` returns rc=2 on nine distinct failure paths, has no result file, and carries `valid_verdicts: []` — a declaration meaning the verdict vocabulary is unconstrained. The manifest marks `scope-manifest.md` as `primary: true`, conflicting with ADR-054 §5's requirement that the primary output is the v2 JSON result file. The plugin communicates run metrics (`goal_len`, `platform_count`) only via `emit_event "plugin.result"` — a sidecar channel, not the primary result. Under v2, plugin-specific detail belongs under a namespaced `data` field in the result file (ADR-054 §5). Lib functions (`_intake_create_workspace_branch` and friends in `lib/`) return their own error codes; those are internal and are NOT narrowed by this issue — only `intake_run`'s engine-facing rc is narrowed.

`scope_manifest` and `intake_goal` keep their declared IDs, types, and paths. Downstream consumers (build, plan, review-lens, review-report, security-lens, impact) declare these inputs by ID and are unaffected. `inputs: []` is unchanged; `platforms.json` is a runtime side-channel, not a declared input.

`provides.role: intake` and all 17 `provides.events` entries are already declared in the manifest and must be preserved as-is (guards). The manifest currently has no `hooks.cleanup` key and no comment recording that absence; ADR-054 §7 requires the absence be recorded explicitly with a comment — the deploy-release pattern is the model. The current plugin.sh constructs `_intake_art="$(dirname "${2:-}")/artifacts"` — after migration this resolves from `ZBUILD_ARTIFACT_DIR` (engine-provided) with the dirname expression as a fallback only.

**Decision.** Migrate test-first per CLAUDE.md:
1. **`intake-test.sh`** — write failing assertions (rc=1, result file on all paths, manifest structure, golden snapshot, router-knob wiring, cleanup-comment grep, provides-role/events guards, no-consumer-path-construction grep, `data` field structure) before touching any implementation.
2. **`manifest.yaml`** — add `result_contract: 2` under `provides:`, add `config.router.{timeout_s: 120, max_turns: 0}`, replace `valid_verdicts: []` with `[pass, fail]`, add new `intake-result.json` output (`primary: true`) before `scope_manifest`, remove `primary: true` from `scope_manifest`, add ADR-054 §7 comment in `hooks:` recording cleanup absence.
3. **`plugin.sh`** — add `_intake_write_result` helper; resolve `artifact_dir` from `ZBUILD_ARTIFACT_DIR` env var with dirname fallback; call `_intake_write_result` on all six exit paths with correct verdict/disposition/data; change all `return 2` in `intake_run` to `return 1`. The `data` object carries `goal_len` and `platform_count` on the success path; on failure paths it carries whichever fields are available at that point (empty object or partial values before state is derived).

Exit-path verdict/disposition mapping: no-goal+no-issue → fail/misconfigured; closed/locked issue → fail/unavailable; failed fetch → fail/unavailable; missing state_file → fail/broken; empty-after-sanitization → fail/broken; branch refused → fail/misconfigured; success → pass/complete.
Where a design decision above conflicts with the plan, follow the design decision.
