#### red-team (score: 5/10)
- [high] plugins/agent/review-aggregator/plugin.sh:367 — The string \`verdict\` is split across two \`printf\` calls at module load time specifically to evade the coercion-vocabulary grep in \`review-aggregator-test.sh\` SPEC-3 (line 99: \`grep -qiE '...|verdict' plugin.sh\`); the design doc explicitly required removing \`verdict\` from that grep instead, so this circumvents a defence-in-depth guard rather than updating it honestly — any future illegitimate use of \`verdict\` hidden behind a variable will equally escape the guard.
- [medium] plugins/agent/review-aggregator/plugin.sh:436 — The legacy discovery path replaces the old \`shopt nullglob\` glob with a \`find -regex '.*/lens-[^/]*\.json$'\` pattern that achieves identical in-code path construction from \`artifact_dir\`; SPEC-5's grep checks only for the literal function name \`_ra_collect_lenses_glob\` and the glob token \`lens-*\`, so the new regex evades both checks while the issue acceptance criterion states 'the plugin constructs no artifact paths in code' and the design required this path to be removed entirely.
- [medium] tests/unit/review-aggregator-test.sh:87 — SPEC-3's runtime guard (\`jq -e '.verdict'\`) passes because the v2 envelope — which does add a \`verdict\` field — is only written when \`ZBUILD_STAGE_INPUTS\` is set, and SPEC-3 runs without it; in production (engine dispatch), the plugin writes \`verdict: complete\` into the primary output, but no existing test drives the plugin as a v1 invocation and then checks the runtime guard holds — the two guards (source-level grep, runtime jq check) now pass for different reasons and neither individually covers the full production path.
- [low] plugins/agent/review-aggregator/plugin.sh:370 — The interrupt handler \`_ra_interrupt_handler\` ignores the two arguments the \`_stage_signal_fire\` dispatch passes it (\`$STAGE_SIGNAL_DISPOSITION\` and \`$STAGE_SIGNAL_REASON\`), instead hard-coding \`disposition:interrupted\` and \`reason:signal_interrupt\`; if the shared constants in \`stage-signal.sh\` are ever changed, the handler silently diverges from the rest of the framework without a compile-time or test-time signal.
- [low] tests/unit/review-aggregator-roster-test.sh:152 — SPEC-3 in the roster test still asserts \`"2"\` lenses from the legacy path (\`[SPEC-3] fallback glob collected the 2 lens-*.json files\`); the design plan explicitly specified this should become \`"no ZBUILD_STAGE_INPUTS + no group env → empty report, rc 0"\` after migration, so the test description and assertion are inconsistent with the intended post-migration contract.

#### scope (score: 8/10)
- [medium] plugins/agent/review-aggregator/plugin.sh:367 — The design (step 4) planned to update \`review-aggregator-test.sh\` SPEC-3 to remove \`verdict\` from its coercion-vocabulary grep; instead \`plugin.sh\` constructs the string \`"verdict"\` from two \`printf\` calls at module level (\`_RA_V2_ESTATUS_KEY\`) specifically to avoid matching that unupdated grep — the comment names this explicitly. This is production-code obfuscation compensating for a test that was planned to be updated but wasn't; it is beyond the issue's stated approach and couples the plugin's source shape to an old test's grep pattern.
- [low] plugins/agent/review-aggregator/plugin.sh:428 — The design describes the fallback hierarchy as 'ZBUILD_STAGE_INPUTS → roster (glob fallback gone)' and planned to update \`review-aggregator-roster-test.sh\` SPEC-3 from 'no group env → legacy glob' to 'no ZBUILD_STAGE_INPUTS + no group env → empty report, rc 0'; the implementation instead introduces a third 'legacy' discovery branch that actively scans for \`lens-[^/]*.json\` files via \`find -regex\`, preserving near-glob behaviour for existing tests that were not updated to provide ZBUILD_STAGE_INPUTS — a fallback path the design did not include and the header comment at line 412 claims was removed.

#### security (score: 9/10)
- [medium] plugins/agent/review-aggregator/plugin.sh:367 — 'verdict' is deliberately split across two printf calls (\`printf 'verd'; printf 'ict'\`) specifically to evade the coercion-vocabulary grep guard in review-aggregator-test.sh SPEC-3; the design document directs removing the token from the guard, but the implementation circumvents the guard instead, leaving SPEC-3 passing while it no longer enforces its stated constraint — any future coercion token that also happens to spell the same word via fragmentation will pass undetected.

#### sre (score: 7/10)
- [low] plugins/agent/review-aggregator/plugin.sh:450 — stage_signal_begin return code is not checked; if a guard is already active (nested or re-entrant invocation), the trap is silently not registered and a SIGTERM during aggregation will not write the degraded v2 result — the same unchecked pattern exists in security-lens and deploy, so this is not introduced here, but the new trap work makes the gap more consequential.
- [low] plugins/agent/review-aggregator/plugin.sh:475 — The v2 envelope (result_contract:2, verdict, disposition, reason) is injected only when ZBUILD_STAGE_INPUTS is set; a roster-fallback run without ZBUILD_STAGE_INPUTS produces a v1-shaped output while the manifest now declares result_contract:2, creating a contract mismatch for any caller that trusts the manifest declaration — introduced by this change, though the engine always sets ZBUILD_STAGE_INPUTS for v2 dispatches so production is unaffected.
- [low] plugins/agent/review-aggregator/manifest.yaml:18 — The description block still reads 'Globs the lens group's lens-<name>.json results from the shared artifacts dir' — the glob is gone; operators reading the manifest for incident triage will be misled about discovery behaviour; the inputs comment at line 81 carries the same stale text.
- [low] plugins/agent/review-aggregator/plugin.sh:360 — _ra_out_json_ref and _ra_out_md_ref are module-level variables initialised at source time and overwritten on each _review_aggregator_run_inner call; if two invocations ran in the same shell process (possible in some test harness configurations), the interrupt handler from the first call would silently write to the second call's paths after the first call finished — introduced by this change, low production risk given the single-process dispatch model.
- [low] plugins/agent/review-aggregator/plugin.sh:505 — The plugin.result event (including lens_count and discovery) is emitted after stage_signal_end; a SIGTERM arriving in that window resets the trap to default, terminates the process before emit_event executes, and the event is lost — the v2 result file still records the interruption, but the event stream has a gap for late signals; this is a new exposure created by moving stage_signal_end earlier in the function.
