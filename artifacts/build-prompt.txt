### zBuild — Vision

> The North Star for zBuild — it steers how zBuild is built. The README distills it; the wiki references it; every pipeline run is steered by it.

#### Intent
zBuild turns a delivery process into data — templates and plugins — so software is built the same disciplined way every time. We build zBuild the way zBuild builds: a minimal core, with all behavior plugin-delivered and template-composed. A good change is small, aligned to the spec, proven by a test, and wired into the live path — never scaffolding that looks finished but does nothing.

#### Principles
- **Target-agnostic by contract** — zBuild builds *any* repository, not itself; the engine and plugins never assume the target's language, layout, or that zBuild is the target. Target knowledge lives in data — templates, config, per-repo overrides — never in code.
- **Spec wins over drift** — KEEPERS, ARCHITECTURE, and the ADRs are the source of truth; when code disagrees, the code changes, not the spec.
- **Small engine, behavior at the edges** — keep the core tiny; add capability as plugins composed in templates, never by growing the engine.
- **Safety is structural** — all model-bound text passes one redaction chokepoint; state is atomic and resumable; scope is governed at every boundary.
- **Models are data, not code** — selection flows through the router and config tiers; never hardcode a model name.
- **Prove behavior, then wire it** — every change ships a test that fails without it and connects to the live path; green-but-inert is a defect.
- **Fail closed, never silent** — gates block on real problems and say why; bounded cycles and recovery drive work to done.
- **Dogfood every change** — build zBuild with zBuild; if the pipeline can't ship it, fix the pipeline.

### Rules
These are this repository's rules (.zbuild/prompts/rules.md). Work that
breaks one is wrong, whoever wrote it.

- Bash only, and match the file you are in: 4-space indent, LF line endings, a final newline, no trailing whitespace (.editorconfig). Everything must pass `shellcheck` with the repo's .shellcheckrc.
- Never pipe anything into `grep -q`, and never pipe into a bare `head`, in any `.sh` file, test files included. The reader exits early, the writer takes SIGPIPE, and under `set -o pipefail` the line fails for a reason nothing logs. Use a here-string instead: `grep -q PATTERN <<< "$var"`, or run grep on the file directly: `grep -q PATTERN "$file"`. `tests/unit/sigpipe-antipattern-guard-test.sh` fails the suite on any violation; a genuinely safe pipe is annotated `# sigpipe-ok: <reason>`.
- Never name a model (haiku, sonnet, opus, …) in code; model selection goes through core/router and config/models.json.
- A test must be able to fail: assert what is required, never what the code happens to do.
- Never edit anything under `legacy-DoNotUse/`.

#### Facts about this repo
- `ZBUILD_*` environment variables are set by the engine at dispatch (the artifact dir, the stage's input index `ZBUILD_STAGE_INPUTS`, the issue, the run). They are trusted engine inputs, not user or attacker input.
- A stage never names another stage's output — not its output name, not its file. The engine hands every stage every earlier stage's latest output, and a stage finds what it needs by what it contains (scripts/lib/earlier-output.sh; ADR-055 §1). A plugin that names another stage's output is a defect.
- Every stage writes a v2 result (`result_contract`, `verdict`, `disposition`, `reason`, detail under `data`) on every exit path, and exits 0 or 1 (ADR-054).
- `[SPEC-n]` / `[#<issue>/SPEC-n]` tags in a test tie an assertion to one issue's acceptance contract. A tag that belongs to another issue must never be changed or removed.

# Design — Issue #1760: Fix loop condition op validation to ADR-027's eight ops

## Architectural decision summary

**Goal.** Validate `abort_when.op`, single-condition `until.op`, and every
condition's `op` in multi-condition `exit_when` at template load against the
eight-op set ADR-027 §5 specifies — `eq | neq | gt | gte | lt | lte | contains |
matches` — and implement all eight in every runtime evaluator with a refusing `*)`
branch.

**Context.** ADR-027 §5 declared the supported op set in June 2026. The engine
was partially updated: `ne` (wrong spelling) and `in` (not in ADR-027) appear in
the evaluators and load-time checks; `gt/gte/lt/lte/contains/matches` are absent.
The bug: `abort_when` has no load-time op check at all in `template.sh`, so an
unknown op silently never fires. The evaluators' missing `*)` branch means a
typo evaluates as "never matches" — the cycle runs to max_iterations with no
indication of why the predicate never fires.

**Decision.**
- **template.sh `_tpl_validate_cycles`**: add op validation for abort_when (read
  from the AW| side-channel vars already populated); add op validation for
  single-condition `until.op` (currently missing); widen multi-condition
  exit_when from `eq|ne|in` to the full eight-op set. Each check emits an error
  naming the loop, the field, the bad op, and the valid set, then returns 1.
- **cycle-orchestrator.sh `_cycle_load_template`**: widen multi-condition
  exit_when check from `eq|ne` to the eight-op set; widen single-condition until
  check from `eq|ne` to the eight-op set; add abort_when op check (currently
  absent).
- **cycle-orchestrator.sh evaluators** (`_cycle_eval_one_condition`,
  `_cycle_check_until`, `_cycle_check_abort_when`): rename `ne` to `neq`;
  remove `in`; add `gt|gte|lt|lte|contains|matches` with numeric guards on the
  numeric ops; add a `*)` branch that emits an error and returns 1.
- **ADR-027**: add `## Enforced by` section naming the enforcement tests;
  remove ADR-027 from `config/adr-enforcement-baseline.txt`.

No new public surface is introduced. All changes are confined to two existing
engine files. The valid op `eq` is unchanged everywhere; all existing templates
and tests use only `eq` and are unaffected.



## Findings

**Plan scope is complete.** No files outside the seed scope pin the old op set.
Existing tests all use `op: eq` (remains valid); the golden files reference
`op=eq` (unchanged). `tests/unit/core-pipeline-template-cycles-test.sh` pins
`until.op=eq` (line 65) — `eq` stays valid, so that test is unaffected and does
not need to be in scope.

**`ne` and `in` are removed.** Neither spelling appears in any shipped template
(`config/templates/`). `ne` appears only in the evaluators and load-time checks
in the two engine files; `in` appears only in those evaluators (added via #1987,
never declared in ADR-027). No template or test fixture uses them.

**abort_when load-time op check is entirely new.** The AW| row handler in
`template.sh` stores the op into `_TPL_CYCLE_ABORT_WHEN_OP_<safe>` but
`_tpl_validate_cycles` never reads it for validation. The fix adds a check there
(after the exit_when/until validation block).

**cycle-orchestrator.sh `_cycle_load_template` has no abort_when op check.** The
`_cycle_load_template` function validates the abort_when stage membership
implicitly (through _CYCLE_STAGES) but does not validate the op field. Adding it
mirrors the exit_when pattern already in that function.

**No event-schema changes.** The reason tokens (`until_op_invalid`,
`exit_when_op_invalid`) are already in use; no new event types are needed. An
`abort_when_op_invalid` reason token is a natural addition but requires no schema
entry (the `cycle.config.invalid` event type is already registered).
Where a design decision above conflicts with the plan, follow the design decision.
