## Notes
1. Router budget defaults in manifest (step-4): the issue says 'router budgets resolve from the manifest, and the template override still wins'. The manifest config.router values are the plugin's own defaults; the template's per-stage router: block already has the same values (timeout_s:600, max_turns:45, retries:1 in simple.yaml). The manifest values are a safety net when no template override exists — they do not conflict with the template because the template wins. retries:1 is NOT added to the manifest because the issue explicitly says impact 'no longer carries its own router.retries' (Folds in §, updated 2026-09-29). Only plan's manifest carries retry_on_exhaustion/retries.
2. Inputs (step-6): impact.run currently constructs '$state_dir/scope-manifest.md', '$artifacts_dir/design.md', '$artifacts_dir/plan.json'. With name-matched inputs the engine resolves those from the declared ids (scope_manifest, design, plan) and hands them in via ZBUILD_STAGE_INPUTS. The outer impact_run reads from the index; _impact_run_inner still takes explicit path args (unit-testable interface preserved).
3. Cleanup hook: impact holds no live resources (no spawned processes, no locks, no open handles beyond what atomic_write closes). The issue says 'if it has nothing to free, the hook is absent and that is recorded, not implied.' So no cleanup hook is added to manifest — instead a comment is added under hooks explaining this.
4. Golden snapshot (step-9): no golden files for impact were found in tests/golden/. If none exist, this step records that the before/after diff was verified by running the passing-run scenario manually and observing only additive field changes. The test confirming 'behaviour is unchanged' may be an existing integration test or a new one.
5. stage_signal_begin is already available via plugin-bootstrap.sh; no additional source line is needed in plugin.sh.
6. rc ∈ {0,1}: the current plugin uses return 2 in _impact_run_inner for contract-violation early exits. These all become return 1. impact_run currently returns 2 when state_file is absent — this becomes return 1 as well, after writing the v2 result.
7. 'data' field in v2 result: for impact, the relevant plugin-specific detail is the missing[] array and the verdict breakdown. The data field should carry at least missing_count on the non-error success path. For error/broken paths it can be an empty object {} or omit data entirely — teardown uses a targets array; plan omits data on failure paths.
8. The acceptance criterion 'Reddens at the merge-base' means the tests added in steps 1-3 must fail on the unmodified tree. The plan orders tests before implementation to satisfy this. The 'npm test green with the tree committed first' criterion means the full suite must pass after all changes are committed.

## DESIGN DECISIONS (from the design stage — honor these directives; they refine the plan)
# Design: Migrate impact plugin to contract v2 (#1838)

## Architectural Decision Summary

**Goal.** Migrate `plugins/agent/impact` to the ADR-054 contract v2 shape: one result file on every exit path, `disposition` from `router_reason_disposition`, `rc ∈ {0,1}`, router budgets declared in the manifest, inputs read from the engine's index (`ZBUILD_STAGE_INPUTS`), signal handling via `stage_signal_begin/end`, and no artifact paths constructed inside plugin code.

**Context.** Impact is the only agent plugin remaining at v1 in the F-wave migration (#1833–#1849). Its `impact_run` currently derives paths from `state_file` (the v1 calling convention), writes bare `schema_version:1` envelopes on router failure paths, has no signal guard, returns `rc=2` on early exits, and has no `config.router` defaults in its manifest. The three integration tests that call `impact_run "impact" "$STATE_FILE"` directly will need their setup updated to provide `ZBUILD_STAGE_INPUTS` and `ZBUILD_ARTIFACT_DIR`.

**Decision.** Follow the plan's 10-step sequence (test-first, then implementation). Split `impact_run` into a signal-guarded wrapper and a `_plan_run_entry`-style entry function. Add `_impact_write_result` and `_impact_input` helpers modelled on their plan counterparts. Add `result_contract: 2` and a `config.router` block (timeout\_s: 600, max\_turns: 45; no retries — the template wins and the plan explicitly says impact no longer carries its own `router.retries`) to the manifest. Update the three integration tests whose `impact_run` call site assumes the old state_file derivation, and update the router-timeout test whose assertion on `.router_rc` breaks when the router failure paths switch to the v2 result shape (which carries `disposition` + `reason` but not `router_rc`). The manifest `config.router` values are defaults that sit below the template accessor in the `_route_resolve_knob` chain (`template > env > manifest > constant`); simple.yaml's per-stage `timeout_s: 600`, `max_turns: 45`, and `retries: 1` continue to win.
