# write-boundary-watch.txt — locations the engine sweeps for out-of-bounds writes
# after each stage dispatch (ADR-058 C9, #1809).
#
# ADR-058 C12: every location here is SHARED with other processes, so a hit is
# RECORDED (stderr, ZBUILD_WRITE_BOUNDARY_LOG, stage.write_boundary.unattributable
# reason=shared_location) and never fails the stage — mtime says when, never
# who. What fails a stage is a change to the run's own worktree by a stage that
# does not declare capabilities.writes_repository; that check reads git, not
# this list. Adding a root here widens what is observed, never what halts.
#
# One entry per line; blank lines and # comments are ignored.
# Format: <path>[ maxdepth:<N>]
# Variables are expanded at sweep time: ${VAR} references the runtime environment.
# ${TMPDIR:-/tmp} is expanded to TMPDIR when set, otherwise /tmp.
#
# Three-tier override (highest to lowest priority):
#   ZBUILD_WRITE_BOUNDARY_WATCH env var (path to alternative file)
#   ~/.zbuild/write-boundary-watch.txt (user/operator override — replaces)
#   this file (shipped engine default)
#
${HOME} maxdepth:1
${HOME}/.zbuild
# NOT the system temp. C9 dropped these two roots and C10 (#1809 follow-up)
# tried to restore them once the engine's own temps were in bounds. That attempt
# was MEASURED on ubuntu CI and reverted; recording the evidence so the next
# person does not spend the same two runs on it.
#
# C10 fixed the half C9 named: engine code in a scrubbed child now gets a
# run-scoped TMPDIR and no longer writes here. That was necessary and is not
# what failed.
#
# What failed is that `/tmp` is not ours. With TMPDIR unset — every ubuntu
# runner — it is the shared temp for every process on the box: git, gh, node,
# npm, the Actions agent itself. Two integration runs halted on
#   stage=intake path=/tmp/tmp.XXXXXXXXXX
# the default BARE-mktemp name. `intake` contains no mktemp at all; the files
# were another process's, and the stage was merely what happened to be
# dispatching. The C10 settle probe caught one of them and missed its twin,
# because a writer that finishes before the dispatch returns leaves nothing live
# to witness. No amount of attribution logic recovers authorship that mtime
# never recorded — which is why C12 removed the probe and stopped halting here.
#
# So the coverage gap C9 named is real and stays open: a stage that hardcodes
# /tmp is still undetected here. Closing it needs authorship, not a better
# watch list — and until then, watching a directory the whole machine writes to
# hands any passing process the ability to kill a run.
#
# An operator on a dedicated machine can opt in via the override file, which
# REPLACES this list:
#   ${TMPDIR:-/tmp} maxdepth:1
#   /tmp maxdepth:1
${PWD} maxdepth:1
# The engine root at 2, per the issue's sweep spec. _ZBUILD_WB_ROOT is set by
# core/pipeline/write-boundary.sh; the built-in fallback list already carried
# this entry, so without it here the shipped config swept less than the default.
${_ZBUILD_WB_ROOT} maxdepth:2
