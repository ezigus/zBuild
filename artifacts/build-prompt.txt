### zBuild — Vision

> The North Star for zBuild — it steers how zBuild is built. The README distills it; the wiki references it; every pipeline run is steered by it.

#### Intent
zBuild turns a delivery process into data — templates and plugins — so software is built the same disciplined way every time. We build zBuild the way zBuild builds: a minimal core, with all behavior plugin-delivered and template-composed. A good change is small, aligned to the spec, proven by a test, and wired into the live path — never scaffolding that looks finished but does nothing.

#### Principles
- **Target-agnostic by contract** — zBuild builds *any* repository, not itself; the engine and plugins never assume the target's language, layout, or that zBuild is the target. Target knowledge lives in data — templates, config, per-repo overrides — never in code.
- **Spec wins over drift** — KEEPERS, ARCHITECTURE, and the ADRs are the source of truth; when code disagrees, the code changes, not the spec.
- **Small engine, behavior at the edges** — keep the core tiny; add capability as plugins composed in templates, never by growing the engine.
- **Safety is structural** — all model-bound text passes one redaction chokepoint; state is atomic and resumable; scope is governed at every boundary.
- **Models are data, not code** — selection flows through the router and config tiers; never hardcode a model name.
- **Prove behavior, then wire it** — every change ships a test that fails without it and connects to the live path; green-but-inert is a defect.
- **Fail closed, never silent** — gates block on real problems and say why; bounded cycles and recovery drive work to done.
- **Dogfood every change** — build zBuild with zBuild; if the pipeline can't ship it, fix the pipeline.

### Rules
These are this repository's rules (.zbuild/prompts/rules.md). Work that
breaks one is wrong, whoever wrote it.

- Bash only, and match the file you are in: 4-space indent, LF line endings, a final newline, no trailing whitespace (.editorconfig). Everything must pass `shellcheck` with the repo's .shellcheckrc.
- Never pipe anything into `grep -q`, and never pipe into a bare `head`, in any `.sh` file, test files included. The reader exits early, the writer takes SIGPIPE, and under `set -o pipefail` the line fails for a reason nothing logs. Use a here-string instead: `grep -q PATTERN <<< "$var"`, or run grep on the file directly: `grep -q PATTERN "$file"`. `tests/unit/sigpipe-antipattern-guard-test.sh` fails the suite on any violation; a genuinely safe pipe is annotated `# sigpipe-ok: <reason>`.
- Never name a model (haiku, sonnet, opus, …) in code; model selection goes through core/router and config/models.json.
- A test must be able to fail: assert what is required, never what the code happens to do.
- Never edit anything under `legacy-DoNotUse/`.

#### Facts about this repo
- `ZBUILD_*` environment variables are set by the engine at dispatch (the artifact dir, the stage's input index `ZBUILD_STAGE_INPUTS`, the issue, the run). They are trusted engine inputs, not user or attacker input.
- A stage never names another stage's output — not its output name, not its file. The engine hands every stage every earlier stage's latest output, and a stage finds what it needs by what it contains (scripts/lib/earlier-output.sh; ADR-055 §1). A plugin that names another stage's output is a defect.
- Every stage writes a v2 result (`result_contract`, `verdict`, `disposition`, `reason`, detail under `data`) on every exit path, and exits 0 or 1 (ADR-054).
- `[SPEC-n]` / `[#<issue>/SPEC-n]` tags in a test tie an assertion to one issue's acceptance contract. A tag that belongs to another issue must never be changed or removed.

### When a finding does not reproduce
If a failing stage names a test and that test PASSES when you run it on this
tree, say so and stop. Answer that finding, on its own line before the sentinel:

    ANSWER <stage> finding <n>: nothing to do — not reproduced: <the path you ran>

one line per finding. This is a REPORT, not a verdict: the pipeline re-runs the
stage that raised the finding to check. Do not keep searching for the cause of
a failure you cannot produce, and do not change code to chase one.

### When a test is wrong
If a test fails on code that already does what its requirement says — the test
itself cannot pass — do not change the code to chase it; you may not change the
test. Answer that finding as soon as you are sure, on its own line before the
sentinel, and stop working on that test:

    ANSWER <stage> finding <n>: nothing to do — the test is wrong: <test file>: <why>

Say exactly why it cannot pass. The stage that owns the tests is given this
answer, and fixes the test.

### Running tests
- Do NOT run `npm test`, the full suite, or `npm run lint` — the pipeline
  runs them and their results are under Previous work.
- Start from the test files listed under Previous work, and the requirements
  each covers: they fail on the code as it is now; do not run them to find that
  out. Run a test only after you change the code it checks, and only that test
  file. A command that runs longer than ~2 minutes can cost you the whole call.
- A failed stage under Previous work is red RIGHT NOW on this tree. Start from
  the failing line it quotes.

record, a field, a message — open the code that writes it and use the names
and shapes it really produces, and when it produces them; never assume them.

### DESIGN DECISIONS (from the design stage — honor these directives; they refine the plan)
# Design: #1805 — resume and --from-stage trust-and-rehydrate

## Architectural decision

**Goal:** When a run is resumed (via `--resume`, auto-resume, or `zbuild pipeline resume --run-id`), every stage already marked `complete` in the persisted state must have its artifacts restored from the git state branch into `ZBUILD_ARTIFACT_DIR` before the dispatch loop runs, using the same extraction path the hydrate plugin uses. After that restoration, a `complete` stage whose primary artifact is still absent must exit 1 (fail closed). For `--from-stage <s>`, the same rehydration runs for every stage before `<s>`; if any pre-target stage has no restorable artifact, the runner refuses before dispatching anything. Inside a loop, the cycle orchestrator must restore `cycle_iterations[X].current_iter` from persisted state and begin the iteration loop from that value, not from 1, but ONLY when a resume is active — fresh runs must always start from iter=1.

**Context / gaps (verified against current tree):**
- Gap 1 — runner.sh resume entry: disarms sentinel, emits `pipeline.resume`, NO artifact restoration. **Fixed in implementation** — `_runner_resume_rehydrate` defined at runner.sh:1702 and called at runner.sh:2838.
- Gap 2 — runner.sh stale-artifact branch warned+continued; after rehydration the right behaviour is exit 1. **Fixed in implementation** — exit 1 at runner.sh:3827–3832.
- Gap 3 — runner.sh from-stage path: no artifact check or rehydration. **Fixed in implementation** — `_runner_from_stage_preflight` at runner.sh:1727.
- Gap 4 — `_cycle_orchestrator_run_body` reads `current_iter` unconditionally (cycle-orchestrator.sh:2325–2329), breaking nested loops. **NOT YET FIXED** — guard with `_ZBUILD_RESUME_ACTIVE` must still be added (step 6), and runner.sh must export `_ZBUILD_RESUME_ACTIVE=true` after line 2838 (step 7). The test at resume-loop-state-test.sh:76 must also export `_ZBUILD_RESUME_ACTIVE=true` before calling `cycle_orchestrator_run` (step 9).
- Gap 5 — ADR-006 and ADR-050 not amended. **Fixed in implementation.**
- Gap 6 — `plugins/tool/hydrate/plugin.sh` line 162 calls `_artifact_persist_put_back` directly but no test fails when the file is reverted to calling `_hydrate_put_back` inline. **NOT YET FIXED** — add SPEC-13 sentinel-mock delegation test (step 5).

**Decision:**
Extract the copy logic from `_hydrate_put_back` (plugins/tool/hydrate/plugin.sh) into a new `_artifact_persist_put_back <from> <to>` function in `core/state/artifact-persist.sh` (which the runner already sources). Redirect the hydrate plugin's `hydrate_run` call site (line 162) to the new function. At the single resume entry point in runner.sh (after `_runner_resume_rehydrate` at line 2838, before `eb_emit_event`), export `_ZBUILD_RESUME_ACTIVE=true` so cycle orchestrators know they are in resume context. In `_cycle_orchestrator_run_body` (cycle-orchestrator.sh:2325–2329), wrap the `_persisted_iter` read with `if [[ ${_ZBUILD_RESUME_ACTIVE:-false} == true ]]; then … else _start_iter=1; fi` — only use persisted iter when actively resuming; otherwise start at 1. Change the stale-artifact branch from warn+continue to exit 1. Add a `_runner_from_stage_preflight` function called before the dispatch loop when `--from-stage` is active. Amend ADR-006 and ADR-050 to document these decisions.
